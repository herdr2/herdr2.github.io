## 1. 全局 Core AI 助手：Herdr2 的必配核心中枢

:::note
**强烈建议在首次上手时就完成 Core AI 配置——AI 能力是 Herdr2 的核心！**
除了具体写代码的主编码 Agent（Claude Code / Codex / Gemini 等），Herdr2 内置了一套全局 **Core AI 控制面**，专门驱动界面与运行时中所有高频、低延迟的智能协同动作。如果不配置 Core AI，Herdr2 会退化为普通多终端壳子，**润色输入、CLI 终端状态精准仲裁、AI 生成 Commit、接力推荐/摘要、回归简报、快照故障定位、Drove 编排辅助**等核心差异化体验都将无法使用。
:::

按 `Ctrl+,` 打开设置，切换到左侧 **「AI 助手」** 即可完成配置（也可在首次启动的欢迎向导中直接配置）：

![设置 -> AI 助手配置页](/images/docs/11-settings-ai.png)

### 1.1 一分钟完成配置

1. 打开 **「启用全局 AI 助手」** 开关（支持本机及已连接的 SSH 远程主机独立配置）。
2. 填入任意 **OpenAI 兼容接口地址**与 **API Key**：
   - **推荐（性价比高、响应快）**：**DeepSeek 官方 API**（Service URL 填 `https://api.deepseek.com/v1`，模型选 `deepseek-chat`）；
   - **也支持**：任意 OpenAI 兼容中转 / 企业内部模型网关，或完全离线的本机 **Ollama / vLLM**（如 `http://127.0.0.1:11434/v1`）。
   - **隐私与安全**：API Key 单独以 `0600` 权限保存在本地 `ai.key` 文件中（不写入明文配置）；同时支持开启**发送前自动脱敏**，在发送终端日志、Diff 或对话片段前自动把 API Key、Bearer Token、PEM 私钥与 URL 凭据替换为 `<REDACTED>`。
3. 点击 **「测试连通性」** 并 **「保存」**，系统会自动拉取可用模型列表。
4. 推荐将 **思考强度** 保持在 `低` 或 `默认`：Herdr2 会在终端状态分类、提示词润色等高频轻量任务中自动压低推理延迟，兼顾秒级响应与极低 Token 成本。

### 1.2 配置 Core AI 后全面解锁的 7 大核心能力

| 核心能力 | 触发方式 | 解决什么痛点 |
| --- | --- | --- |
| **✨ AI 润色输入（核心高频）** | `Ctrl+Alt+P`（macOS `Cmd+Alt+P`）或点击「润色输入 / 润色」，支持 `Ctrl+Alt+U` 反悔恢复 | 结合当前会话上下文，把碎片化口语一键改写为结构清晰、含约束的工程 Prompt（原生 CLI 终端内也可直接原地替换！） |
| **非协议 CLI 状态语义仲裁** | 自动在后台静默运行 | 当终端里的 CLI 工具静默且无协议上报时，自动识别是否卡在权限提问、报错或仍在思考，精准点亮侧边栏红标 |
| **Git 提交说明一键生成** | 右侧「变更」面板底部点击 **「AI 生成」** | 读取真实工作区 Git Diff，直接起草规范准确的 Commit Message |
| **接力/分叉智能推荐与摘要** | Handoff 弹窗右上角点击 **「AI 推荐」** | 分析近期对话与代码改动，推荐最佳目标 Agent 与交接模式，并生成精简交接包 |
| **智能体语义标题与进度摘要** | 自动在后台静默运行 | 为左侧智能体列表和顶部标签页生成一眼看懂的中文语义标题与进度微摘要 |
| **Catch-up 回归简报** | 命令面板运行 `agent.briefing` | 离开工位回来后，一键汇总所有待审批阻塞项、已完成任务与可批量审批的建议 |
| **快照定位与 Drove 编排辅助** | 快照面板「定位故障」/「设置 → Drove」点「AI 一键配置」 | 自然语言定位引入 Bug 的罪魁轮次，以及自动为 Drove 多角色匹配模型、排查死循环与冲突 |

## 2. 重点功能详解：AI 润色输入（Prompt Polish）

和 AI 编程工具协作时，写出一句「背景完整、约束明确、输出边界清楚」的 Prompt 往往能把一次成功率从 40% 拉到 90%——但真正在高频写代码时，没人愿意每次都手动敲一大段结构化需求。

Herdr2 的 **「润色输入（`prompt.polish`）」** 就是为此设计的杀手级高频功能：**你只管按最省事的大白话打草稿，按下快捷键，让轻量 Core AI 结合当前项目的真实上下文替你瞬间扩写成高质量工程指令。**

### 2.1 为什么它比「复制到网页里润色」强得多？

1. **自带实时上下文感知，不只是文字改写**：
   触发润色时，Core AI 会自动读取当前会话的**工作目录（`cwd`）、近期对话轮次、最近执行的工具输出，以及原生 CLI 终端屏幕尾部内容**。
   哪怕你只写了半句含糊的指代（比如 *「刚才那个报错修一下，顺便把边界测了」*），它也能准确结合刚才的报错和文件路径补全具体目标，而不是瞎编。
2. **原生 CLI 终端内「原地润色」——零复制、零切换**：
   这是 Herdr2 最独特的能力之一：即便你正在 **Claude Code / Codex / Gemini 等原生 PTY 终端**里敲字，也不需要切出终端！
   按下快捷键后，Herdr2 直接读取 CLI 输入框里的未发送草稿（完整支持**多行输入与编号列表**），在窗口底部弹出轻量悬浮进度条（可随时取消），完成后**原地替换**终端输入框中的内容——你确认无误直接按回车即可发送！
   > 如果你在润色请求返回前又继续敲了新字，Herdr2 会自动检测输入变化并**主动放弃覆盖**，绝不会弄丢你的最新手打内容。
3. **一秒「反悔」无损还原（Undo）**：
   觉得润色后的表述太啰嗦，或者还是想用原来的说法？立刻按 **`Ctrl+Alt+U`**（macOS `Cmd+Alt+U`）或点击右上角通知里的撤销按钮（`prompt.polish_undo`），原封不动还原润色前的原始草稿。

### 2.2 全场景触发方式一览

| 使用位置 | 触发方式 | 适用场景 |
| --- | --- | --- |
| **原生 CLI Agent 终端**（Claude Code / Codex / Gemini 等） | 点击卡片顶部 **「✨ 润色输入」** 按钮，或按 **`Ctrl+Alt+P`**（macOS `Cmd+Alt+P`） | 日常主力开发，直接原地润色未发送的终端草稿 |
| **无头 ACP 对话框** | 点击输入框右下角 **「✨ 润色」** 按钮，或按 **`Ctrl+Alt+P`** | 派发复杂编码、审查、调研任务前快速结构化需求 |
| **闪念清单（Flash Notes）与弹窗输入** | 点击输入框旁的润色按钮，或按 **`Ctrl+Alt+P`** | 把随手记下的一句话灵感润色成可直接派单的任务描述 |
| **命令行 / 自动化脚本** | 运行 `h2 ai polish-prompt "你的草稿"` | 在外部脚本或终端里按需调用同一套 Core AI 润色引擎 |

### 2.3 实战效果对比（Before / After）

假设你刚在 `order-service` 里让 Claude Code 改完 `src/pricing.py`，接下来想让它补全异常处理和单测：

- **你随手敲的草稿（耗时 3 秒）**：
  ```text
  pricing那个优惠码大小写兼容一下，负数金额别算错了，顺便补单测跑通
  ```
- **按下 `Ctrl+Alt+P` 原地润色后（约 1~2 秒）**：
  ```text
  请修改 `src/pricing.py` 中的 `apply_coupon` 与金额计算逻辑，并补充对应单元测试：
  1. 优惠码匹配前统一做 `strip().upper()` 归一化，兼容前后空格与大小写输入；
  2. 对负数 `subtotal_cents` 或非法数量做防御校验（避免折扣后出现异常金额）；
  3. 在 `tests/test_pricing.py` 中补充小写/含空格优惠码及非法金额的边界用例，最后运行 `python3 -m unittest` 确认全部通过。
  ```
- **觉得太长想改回原稿？** 直接按 **`Ctrl+Alt+U`** 一键复原。

:::tip
**热键被其他软件占用了怎么办？**
在 Windows / Linux / macOS 上，`Ctrl+Alt+P` 有时会被截图工具、输入法或系统热键抢占。Herdr2 启动时会自动探测全局热键占用情况——如果检测到冲突，会自动切换到可用的备选组合键（如 `Ctrl+Alt+R` / `Ctrl+Alt+E`），同步更新 `keys.json` 并弹窗通知你；你也可以随时在 **「设置 → 快捷键」** 中自定义为自己最顺手的按键。
:::

## 3. 上下文接力、会话分叉、旁路讨论与发送上下文

在深度开发中，你经常会遇到这四种痛点：
1. 当前 Agent 对话太长、上下文接近上限或额度耗尽，想换另一个模型/工具继续干，但不想重新把背景讲一遍。
2. 做到一半发现有两个设计方案，想在不破坏主会话的前提下，分别试跑方案 A 和方案 B。
3. 想针对刚生成的某段代码问几个原理性问题，又不想把这些闲聊塞进主任务上下文里干扰编码。
4. 手头已经同时开着多个在跑的 Agent（例如后端 Agent 刚改完接口、前端 Agent 正在等字段，或 A 会话查出了根因想交给正在修代码的 B 会话），不想重新开新会话，只想把这边的最新上下文直接「递过去」。

在任意 ACP 对话或终端顶部点击 **「旁路」 / 「分叉」 / 「接力」 / 「发送上下文」**（或运行 `herdr2 do agent.handoff`），即可呼出对应的**上下文流转弹窗**：

![上下文接力、会话分叉与旁路讨论弹窗](/images/docs/09-handoff-dialog.png)

### 3.1 四种模式对比

| 模式 | 目标会话 | 做了什么 | 典型使用场景 |
| --- | --- | --- | --- |
| **上下文接力（Handoff）** | 新建会话 | 提炼近期对话进展 + 当前 Git 工作区改动为精简交接包，交给**任意新 Agent / 模型**无缝接棒 | 用 Claude 做完架构设计后，切给 Codex 写底层代码；或对话过长时「瘦身重启」 |
| **会话分叉（Fork）** | 新建平行会话 | 从当前轮次（或点击历史消息下的「从此轮分叉」）拷贝上下文开启平行分支，可选**自动创建独立 Git Worktree** | 同时探索两种重构方案；或保留主线不动，在分叉里大胆做破坏性实验 |
| **旁路讨论（Side-chat）** | 右侧只读侧边栏 | 在右侧面板（与文件/变更/快照并列）开启轻量只读探讨，共享背景摘要但**不污染主会话历史、不改动代码** | 边看代码边问「这段锁顺序会不会死锁」，问完即关（也可将结论「合回父会话」） |
| **发送上下文（Send Context）** | **已有在线会话**（CLI / ACP 均可） | 不新建会话，直接把当前会话的近期上下文整理发送给**另一个已经开启的在线 Agent**，并可附带备注/后续指令 | 后端 Agent 改完接口后直接把改动上下文发给已开着的前端 Agent；或把调研/排障结论直接同步给正在编码的会话（支持跨工作区） |

### 3.2 弹窗里的精细控制

- **接力 / 分叉 / 旁路（新建目标）**：
  - **目标 Agent 与模型**：支持跨 14 种预设自由切换，点击右上角 **「AI 推荐」** 可让 Core AI 自动推荐最匹配当前任务的 Agent 与交接模式。
  - **运行方式与打开位置**：选择以 `ACP 对话` 或 `CLI 终端` 启动，在 `新标签页` 或 `右侧分栏` 打开。
  - **接力后收起原会话分栏**：勾选后原会话退居左下角智能体列表保留存档，工作区立刻切到新接力会话。
- **发送上下文（投递到已有会话）**：
  - **选择目标在线 Agent**：列表自动汇总当前全部在线的 **CLI 终端** 与 **ACP 会话**（显示运行状态点、类型徽标与所属工作区，支持跨工作区投递）。
  - **携带上下文范围与备注**：按 `最近 4 轮`、`最近 8 轮`、`最近 15 轮`、`全部` 或 `自定义轮次` 精确裁剪，并在底部填写可选的备注说明或具体指令一并发出；还可选发送后是否立即跳转聚焦到目标会话。
- **分叉 / 旁路的逆向闭环——合回父会话（Merge Back）**：
  - 在分叉或旁路会话顶部点击 **「合回父会话」**，即可把探索出的结论自动提炼注入回原父会话继续推进；若分叉启用了独立 Git Worktree，还可勾选「通知主 Agent 合并 Worktree 分支代码（保留 Worktree 与分支）」。

### 3.3 CLI 一键操作

```bash
# 1. 上下文接力：将 a1 的最近 8 轮上下文接力给 codex 并在新会话中继续执行
h2 handoff a1 --preset codex --recent-turns 8 --prompt "基于当前改动补齐集成测试"

# 2. 会话分叉：在隔离 Git Worktree 中分叉 a1，互不干扰工作区文件
h2 handoff a1 --kind fork --worktree --prompt "尝试用状态机重写折扣计算器"

# 3. 发送上下文：直接把 a1 最近 6 轮上下文转发给已开启的另一个在线会话（支持 CLI t2 或 ACP a2）
h2 handoff a1 --kind send-context --into t2 --recent-turns 6 \
  --note "后端新增了 NEW10 优惠码与校验错误码" \
  --prompt "请按后端最新的接口约定同步更新前端结账页"
```

## 4. 快照与一键回滚（Checkpoints）

让 AI 直接改代码时，最怕的不是某一步写错，而是「改了三轮之后发现第一轮就引入了隐蔽 Bug，却和自己手改的代码搅在一起，不敢轻易 `git reset --hard`」。

Herdr2 内置了基于**隐藏 Git Ref（`refs/herdr2/...`）**的**快照引擎**：
- **零 Git 历史污染**：所有快照只作为隐藏对象保存在 Git 对象库中，**不会产生任何临时 Commit，不改写你的 `HEAD` 或分支历史**。
- **自动 + 手动双轨存档**：ACP 智能体每完成一轮修改会自动打点；你也可以随时点击右上角 **「+ 存档」** 或运行 `h2 checkpoint snap` 给当前工作区贴一个带书签名的快照。

点击主窗口右上角的 **「快照」** 按钮，即可展开完整的轮次时间轴：

![右侧快照面板与轮次纯净 Diff](/images/docs/07-checkpoints-panel.png)

核心功能一览：
1. **轮次时间轴（T0 / T1 / T2…）**：清晰展示每次存档的书签名（如 `T1 重构折扣逻辑前`、`T2 增加折扣上限与测试 +12 -5`）。
2. **纯净轮次 Diff**：点击任意节点，下方立即展示**这一轮独有的真实代码增量**（支持 `直接` / `分栏` 视图切换），剥离无关噪音。
3. **一键恢复（Rollback）**：点击任意历史节点右侧的 **「恢复…」**，可选择仅回滚对话状态，或将**对话与工作区文件同步恢复**到该轮次的精确状态。
4. **自然语言故障定位（Bisect）**：在顶部输入框描述异常现象（如 `哪一轮导致折扣上限单测失败？`）并点击 **「定位故障」**，系统会结合 Core AI 与各轮次纯净 Diff 帮你快速缩小引入 Bug 的罪魁轮次。

### 对应的 `h2 checkpoint` CLI 命令

```bash
# 手动为当前终端/智能体打一个带标签的快照
h2 checkpoint snap t1 --label "重构折扣逻辑前"

# 查看所有轮次快照列表
h2 checkpoint ls t1

# 查看任意两轮之间的纯净 Diff
h2 checkpoint diff t1 --from 1 --to 2

# 一键回滚到第 1 轮状态（含工作区文件）
h2 checkpoint rollback t1 --turn 1 --workspace

# 使用 CLI 执行故障轮次定位
h2 checkpoint bisect t1 --symptom "VIP20 折扣上限测试失败"
```
